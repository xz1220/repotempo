# RepoTempo 已确认界面基准 v1

本基准来自用户已确认的 OpenDesign 版本。它约束外观和已演示的交互，不替代生产系统的身份认证、授权、数据真实性与业务规则。

## 固定参照

- `repotempo-approved.html`：完整交互原型，图片全部内嵌。
- `brand-spec.md`：当前配色与字体。视觉细节有分歧时，以冻结 HTML 的实际显示为准。
- `manifest.json`：文件校验值和关联代码的版本记录。
- 不在这个基准目录内继续“优化”原型。后续获批的设计变更另建 v2，并更新仓库根部指针。

## 已确认的视觉规则

1. 使用 shadcn/ui 组件风格作为参考；这份 HTML 并未安装 React 或 shadcn/ui，迁移时无需强制更换现有技术栈。
2. 浅灰侧栏、白色内容区、石墨文字、少量靛蓝。复用六个 OKLch 颜色变量，不恢复早期深色侧栏和青绿色主题。
3. 顶栏左侧为“工作空间 / 项目库”，右侧为导出和添加项目。不恢复下方独立的大标题、营销标语或“公开快照 · 本地演示”文字。
4. 侧栏只保留品牌、趋势看板、GitHub 项目、头像账户入口和“Star on GitHub ↗”文字链接。不得恢复侧栏分组标题、登录/注册并排按钮和已删除的说明文字。
5. 侧栏导航和头像共用 32px 图标栏、10px 间距；补偿导航边框的 1px 缩进。底部链接与品牌保持共同左边线。
6. 项目采用单列轻分隔列表。项目名、简介和标签为主要阅读区；累计 Star、期间增长和操作采用稳定列宽。
7. 标签保持低对比度的辅助信息外观，无大面积底色或按钮边框；默认四个，允许展开全部。
8. 搜索、观察日期、增长对比和排序默认收在“筛选”中。展开、关闭保留当前条件。
9. 行内关注/已读操作保持小尺寸；不得把所有操作恢复为高强调实心按钮。移动端可扩大隐形点击区域，避免改变已确认的视觉比例。
10. 用户只批准当前文件中实际存在的状态。本次冻结不额外删除仍保留的摘要条，不增加其他未确认布局。

## 需要保持的交互

- 阅读 / 紧凑视图切换，精确标签过滤，空结果与清除筛选。
- 我的关注和显式已读状态；进入详情不自动标记已读。
- 添加项目的 URL 校验、重复仓库处理、错误提示。
- 页码、上一页、下一页和每页数量控件；筛选和排序重置页码，数据减少时修正末页。
- 头像打开账户入口，登录后提供账户菜单、API 访问和退出。
- AK/SK 界面中的创建、有效期、SK 本次展示、复制、撤销和 Agent 指令。

## 原型和生产的明确边界

| 原型中的表现 | 迁移到生产时的要求 |
| --- | --- |
| 20 个公开仓库快照与内嵌头像 | 仅作为参照样本，列表内容来自现有后端。不得用静态示例覆盖数据库。 |
| 默认每页 6 个、4 页效果 | 6 个是演示密度。生产默认每页 20 个按现有业务规则保留；新增页码跳转需后端支持，不能对单页响应切片冒充全量分页。 |
| 邮箱和密码模拟登录、演示账户 | 保留现有 GitHub OAuth 与数字 GitHub ID 白名单。不得发布前端模拟认证，也不自动开放公众注册。 |
| 内存中的 `ak_demo_` / `sk_demo_` | 尚无后端权限。未实现真实鉴权前，生产入口应明确未开放或隐藏，不能生成看似可用的生产密钥。 |
| `/api/v1/*` 和 HMAC 指令 | 属于待实现的方案，不是已存在的 API。需独立实现后端并验证协议后再启用。 |
| 内存 / localStorage 演示状态 | 真实关注、会话和权限接回服务器；浏览器已读记录遵循现有产品行为。 |
| 仅一次快照，增长显示破折号 | 后端有真实历史时照常呈现；缺失值不补零，不删掉真实增长与历史图。 |

## 验收要求

- 对照同样的数据、同样的筛选条件和窗口宽度比较，不因实时 Star 数不同判定外观失败。
- 桌面与窄屏均无横向溢出、重叠、截断；重点覆盖 360、390、430、600、768、820、1024、1366、1440、1920px。
- 检查未登录、真实登录、账户菜单、筛选开/关、空列表、第二页、末页、详情和添加错误状态。
- API 设置在后端完成后另验收：权限、账号隔离、SK 保存/销毁、撤销生效、防重放、有效期和限流。
- 保留当前中英文能力、真实路由、CSRF 与权限校验。视觉变更不得削弱认证。
- 只修实现偏差，不擅自重新设计。冲突优先保护数据、授权和可访问性，并明确报告与视觉基准的必要差异。
